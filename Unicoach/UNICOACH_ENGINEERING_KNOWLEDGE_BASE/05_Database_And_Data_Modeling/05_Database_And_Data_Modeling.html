2. Technology Decision Framework

1. MongoDB (Document DB) vs PostgreSQL (Relational DB)Database Choice
What is it?
MongoDB is a schema-flexible NoSQL document database storing JSON-like BSON documents, optimized for hierarchical, nested data structures.
How does it work & Problem solved?
A student lead document naturally contains nested arrays (notes history, document uploads, conversation logs). In PostgreSQL, this requires 4–6 normalized tables with JOINs. MongoDB stores it as a single document, enabling a simple Lead.findById() vs a complex multi-JOIN SQL query.
What alternatives existed?
PostgreSQL: ACID transactions, JSONB columns — better for financial ledgers. PlanetScale (MySQL): Serverless scaling, but no native document nesting.
Why did we choose this approach?
Lead documents are hierarchical (nested notes, stage history, document lists). MongoDB's document model matches the natural shape of the data, eliminating 80% of the JOINs that would be required in a relational model.
2. Mongoose v8 with .lean() ExecutionORM Strategy
What is it?
Mongoose v8 is a MongoDB ODM that adds schema validation, middleware hooks, and type safety on top of the MongoDB Node.js driver. The .lean() modifier returns plain JavaScript objects instead of full Mongoose document instances.
How does it work & Problem solved?
Without .lean(), Mongoose hydrates every query result into full document objects with getters, setters, virtuals, and prototype methods — consuming 60% more RAM. For read-heavy list endpoints (universities, scholarships), .lean() reduces memory usage by 3x–5x and speeds up execution by the same factor.
What alternatives existed?
Raw MongoDB Node.js driver — faster but no schema validation or middleware hooks. Prisma — excellent TypeScript support but limited MongoDB schema flexibility.
Why did we choose this approach?
Best of both worlds: Mongoose provides schema validation and lifecycle hooks; .lean() provides raw performance for bulk read queries.
💡 Senior Interview Defense: "Explain your database design choices"

"For UniCoach, I chose MongoDB Atlas over PostgreSQL because student lead records are naturally hierarchical — each lead document contains nested arrays of notes, stage history, and document attachments. MongoDB's document model eliminates the multi-table JOINs that a relational schema would require. I run a 3-node replica set on Atlas, providing automatic failover in under 30 seconds and point-in-time recovery via oplog snapshots, giving us RPO under 1 hour. For performance, I apply .lean() on all read-heavy list endpoints, reducing query time and server RAM consumption by 60%."
