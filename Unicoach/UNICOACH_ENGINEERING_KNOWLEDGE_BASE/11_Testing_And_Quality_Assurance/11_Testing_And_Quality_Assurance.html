2. Technology Decision Framework

1. Jest + Supertest vs Mocha + Chai vs PostmanTest Framework
What is it?
Jest is a zero-configuration parallel test runner with built-in assertions and mocking. Supertest wraps an Express app for in-memory HTTP testing without binding to a network port.
How does it work & Problem solved?
Binding to a real TCP port during tests causes random port collisions in CI environments and adds 100–500ms latency per test suite. Supertest passes synthetic requests directly into the Express application handler in-memory, completing in milliseconds.
What alternatives existed?
Mocha + Chai: Requires separate test runner, assertion library, spy library, and coverage tool. Manual Postman: Not automatable in CI pipelines.
Why did we choose this approach?
Jest ships with everything: parallel execution, mocking, coverage, watch mode. Supertest integrates directly with Express. Zero configuration overhead.
💡 Senior Interview Defense: "How do you ensure code quality before releases?"

"UniCoach uses a 5-stage quality pipeline. ESLint runs first for static analysis. Then an automated module integrity checker verifies all 32 Express routes map to existing controller functions — catching the classic 'callback got undefined' boot crash before it reaches production. Jest unit tests cover Zod schemas and utility functions. Supertest integration suites validate every API endpoint in-memory with Twilio and Groq mocked out. Finally, a mandatory production build gate runs Vite on both frontend and admin apps — if any syntax error or broken import exists, the build fails and the git push is blocked."
