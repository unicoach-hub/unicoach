1. HttpOnly JWT Cookie vs LocalStorageAuth Security
What is it?
A browser HTTP-only cookie stores the JWT authentication token with flags that prevent JavaScript from accessing it.
How does it work & Problem solved?
LocalStorage tokens are vulnerable to any XSS attack — an injected third-party script can call localStorage.getItem('token') and steal the session. HttpOnly cookies are inaccessible to JavaScript by browser design. Only the browser's network layer can read and send them.
What alternatives existed?
LocalStorage: Simpler to implement, but OWASP A07 non-compliant. SessionStorage: Same XSS vulnerability as LocalStorage.
Why did we choose this approach?
OWASP A07 compliance and production-grade security for student personal and financial data protection.
2. bcrypt vs SHA-256 for Password HashingCredential Safety
What is it?
An adaptive hashing algorithm specifically designed for passwords that intentionally runs slowly and adds a cryptographic salt to prevent rainbow table and brute-force attacks.
How does it work & Problem solved?
SHA-256 hashes a billion passwords per second on modern hardware. bcrypt is tunable via a "cost factor" (we use 12) that makes each hash take ~250ms. An attacker who steals our database would need 34 years to brute-force a 10-character password.
What alternatives existed?
SHA-256: Extremely fast — useful for checksums, catastrophic for passwords. MD5: Cryptographically broken since 1996.
Why did we choose this approach?
bcrypt is the OWASP-recommended standard for password storage. Cost factor 12 provides a 250ms computation time — imperceptible to a user logging in, but 34 years for an attacker brute-forcing offline.
💡 Senior Interview Defense: "How do you secure user authentication?"

"UniCoach uses a defense-in-depth authentication model. JWTs are stored in HttpOnly cookies — never LocalStorage — making them immune to XSS token theft. Passwords are hashed with bcrypt at cost factor 12, giving 250ms compute time per attempt and making brute-force attacks computationally infeasible. A 3-tier rate limiter blocks credential stuffing at the auth endpoints and protects AI endpoints from cost exhaustion. All inbound data is sanitized against NoSQL injection via express-mongo-sanitize before touching any MongoDB query."
