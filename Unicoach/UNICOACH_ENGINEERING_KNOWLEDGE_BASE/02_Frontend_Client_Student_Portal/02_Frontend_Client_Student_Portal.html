2. Technology Decision Framework

1. React 18 + Vite 8 vs Next.js SSRFramework
What is it?
A client-side rendered Single Page Application (SPA) using React 18 with concurrent features, built and bundled by Vite 8 using the Rolldown Rust-based bundler.
How does it work & Problem solved?
React Router v6 provides client-side navigation with zero full-page reloads. Dynamic imports via React.lazy() ensure heavy pages (Three.js globe, AI chat) only download when visited, reducing initial load to <195kB gzipped.
What alternatives existed?
Next.js 14 (SSR): Better SEO by default, but requires Node.js server for SSR — adding backend complexity. Create React App: Webpack-based, 10x slower builds.
Why did we choose this approach?
Marketing pages use static pre-rendered HTML (SEO via meta tags). The real UX value is in authenticated interactive dashboards — where SSR provides negligible benefit but adds significant operational cost.
2. Three.js WebGL vs CSS 3D Animations3D Rendering
What is it?
Hardware-accelerated 3D WebGL scenes embedded in the hero section and FinalCTA banner using Three.js.
How does it work & Problem solved?
WebGL renders on the GPU compositor, bypassing the browser's CSS layout and paint phases entirely. The globe, particle systems, and 3D objects run at 60fps without causing layout jank on the main thread.
What alternatives existed?
CSS 3D transforms: Limited to flat planes, no real depth, no particle systems. Lottie animations: 2D SVG-based, no WebGL depth effects.
Why did we choose this approach?
Differentiates UniCoach visually in a commoditized market of cookie-cutter education platforms. The immersive 3D experience increases session duration and perceived product quality.
💡 Senior Interview Defense: "Describe your frontend architecture decisions"

"For UniCoach's student portal, I architected a React 18 SPA using Vite 8 with strategic code splitting — Three.js, Framer Motion, and React itself ship as separate cached vendor chunks. Route-level lazy loading reduces initial download to under 195kB gzipped. Three.js WebGL scenes on the hero run at 60fps via GPU compositing. For mobile, I applied responsive breakpoints with hidden classes to prevent avatar and element collisions on sub-640px viewports."
